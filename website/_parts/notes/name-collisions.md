**Two types share each context name.** `TriggerOrchestrator.<Ctx>` is the registration interface your orchestrator implements; its one method is `<ctx>Handlers()`. `<Ctx>` on its own is the context class that holds the role and add-on interfaces your handlers implement. In the same way, `TriggerOrchestrator.Bypassable` is the builder that `TriggerOrchestrator.bypass()` returns, while `<Ctx>.Bypassable` is the add-on a handler implements to switch itself off. An orchestrator that does not implement `TriggerOrchestrator.<Ctx>` still compiles and its trigger still fires, but `run()` does nothing in that context and reports nothing.

**Handlers are known by their simple class name.** The library names a handler by its class name without the outer class, and compares names ignoring case: an inner class `Outer.Inner` is `Inner`. That name is what these match:

- **`TriggerHandler__mdt` rows**, under the object's `TriggerObject__mdt` row. `ApexClassName__c` may hold `Inner` or `Outer.Inner`; both switch off every handler class whose simple name is `Inner`. See [the `ApexClassName__c` format](/api/custom-metadata#class-name-format).
- **`TriggerOrchestrator.bypass().handler(X.class)` and `.orchestrator(X.class)`.** These store the name that `X.class` reports, which for an inner class is `Outer.Inner`, so they never match an inner class. They work for top-level classes; for classes in a namespace this is not verified. For an inner handler class, use its `TriggerHandler__mdt` row or its Bypassable add-on; for an inner orchestrator class, use `TriggerOrchestrator.bypass().sObject(…)`.
- **Recursion budgets** in the update contexts, which are counted per handler name.
- **`getHandlerName()`** on the `TriggerOrchestrator.Error` that a Logger receives.

Two classes with the same simple name, such as the inner classes `AccountRules.Defaults` and `ContactRules.Defaults`, are therefore one handler for all four: switched off together, counted together, and logged under one name. Two instances of one class in a handler list share a name the same way. A class that overrides `toString()` is named by the text before the first `:` of what it returns.
