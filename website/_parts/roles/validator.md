A Validator rejects records; it never changes them.

- **The error method attaches the error itself.** For each record whose predicate returns true, the error method, `addErrorOn<Ctx>(record)`, runs right away. Its record is a `TriggerHandler.Rejectable<X>Record`: it reads everything the predicate could read, and it adds errors with `record.addError(message)` for a record-level error or `record.addError(field, message)` for an error on a field. It has no `put`, so keep writes in Populators.
- **A qualified record must get an error.** The library counts the errors on `getNewSObject()` before and after the error method. If none was added, it throws a `TriggerOrchestratorException`: `<Handler> qualified a record in errorShouldBeAttachedOn<Ctx>When but attached no error in addErrorOn<Ctx>.` It is logged and always rethrown, with or without ContinueOnError, so every record in the chunk fails. The class is private; see [`TriggerOrchestratorException`](/api/trigger-orchestrator#triggerorchestratorexception).
- **Errors accumulate.** `addError` does not throw and does not stop the run. Later handlers still run for the record, and every Validator that rejects it adds its own message. The record is not saved.
- **Field errors on Name and address fields.** `record.addError(field, message)` calls the dynamic `SObject.addError(SObjectField, String)`. On Name and on compound-address fields (tested on Name, BillingStreet and BillingCity) that form loses the field attribution: the save is still blocked and the message still shows, but at record level instead of on the field. For those fields, use the static field form inside the error method, for example `((Account) record.getNewSObject()).Name.addError(message)`. It counts as an attached error.
- **Its Finalizer sees only rejected records.** Every record a Validator qualifies carries an error. For checks across the records of the chunk, such as duplicates within one import, use a Populator with a Finalizer and call `getNewSObject().addError(message)` there.
- **Translated messages.** Pass a custom label: `record.addError(System.Label.MyMessage)`.
