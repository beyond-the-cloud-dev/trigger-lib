- **The shared unit commits once per run**, after the last handler in the list, Dispatchers included. Every trigger invocation is a separate run with its own shared unit, so a DML statement that the platform splits into 200-record chunks commits once per chunk. A commit that fires other triggers starts nested runs, and each of them commits its own shared unit.
- **An own or private unit commits right after this Writer's Finalizer**, or after its last record when it has no Finalizer, and only when at least one record qualified. Its writes land before the shared commit, even for a Writer late in the list, and later handlers can query them.
- **Until a unit commits, its records are not in the database.** Later handlers cannot query what an earlier Writer registered in the shared unit.
- **A failed shared commit fails the save.** It runs outside every handler's error handling, so ContinueOnError does not swallow it and it never reaches `TriggerOrchestrator.Logger`. A DML Lib `DML.Logger` implementation, if the org has one, still sees the failed statement.
- **A failed own or private commit is this Writer's error.** It reaches `TriggerOrchestrator.Logger` under the Writer's name, and it is swallowed only when the Writer implements ContinueOnError.
- **A commit has no savepoint.** When its second statement fails, the first one is already written. If the failure then fails the save, the platform rolls back everything the save did. If ContinueOnError swallows it, the statements that ran before the failure stay.
- **Duplicates.** The shared and private units merge a second `toUpdate` or `toDelete` of the same Id into the first one: fields set in the later registration overwrite, and fields set only in the earlier one stay. An own unit without `combineOnDuplicate()` throws "Duplicate records found during registration. Fix the code or use the combineOnDuplicate() method." at the second registration instead. In a unit with the default statement order, registering the same record twice with `toInsert` or `toUpsert` (the same instance, or two instances with the same Id) throws "Duplicate records found during registration. Fix the code." at commit, with or without `combineOnDuplicate()`.
- **System mode, without sharing, all or none.** The shared and private units ignore the running user's object and field permissions and record sharing, and one failing record fails the commit. For user mode, sharing or partial success, give the Writer an OwnUnitOfWork.
- **Statement order.** DML Lib orders the statements, not the handler list: inserts and upserts first, in waves so that a parent linked with `withRelationship` is saved before its child, then updates, then deletes, then event publishes. A commit costs one DML statement per operation and object type (for upserts, also per external Id field), and for inserts and upserts one per object type in each wave. A unit with nothing registered costs nothing.
- **Your own order.** Give the Writer an OwnUnitOfWork built with `new DML(List<DML.OperationType>)`. Such a unit runs the operations in the listed order, throws at registration for an operation that is not listed, and has no parent-before-child waves: within one operation, object types run in the order they were first registered.
